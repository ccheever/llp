# LLP 0001.000: Retrofit Interview

**Type:** Guide
**Status:** Active
**Systems:** LLP
**Author:** Brent Vatne
**Date:** 2026-08-25
**Related:** LLP 0001, LLP 0000, LLP 0004

## Summary

How `llp-adopt` retrofit actually runs: survey into an evidence deck, interview the maintainer, then draft. The **contract** is [LLP 0001](./0001-adopting-llp.guide.md) (unit of adoption, interview-before-draft, every question names a card, provenance, first-pass size, confirm-before-survey, file-count brake). Everything else in this guide is recipe — skip it if the runtime does not need it.

Journal fields required for `--resume` are the child's only extra contract: `phase`, `interview`, the evidence cards, and rounds completed.

## Evidence deck

> **Recipe (advisory)**

The survey fills `.llp/adopt-run.md` at the adoption root. Cards are `[observed]` plus a *candidate* question. They are not `[inferred]` rationale.

```markdown
### Card: serial photo processing queue
- [observed] `ios/Current/CameraPhotoCapture.swift:20-25` — comment: "overlapping full-res photo pipelines can jetsam small devices"
- Question class: invariants / never-simplify
- Draft question: (see worked example)
```

Inventing "they did this because of Apple's memory guidelines" in the journal is a defect.

### Journal fields (contract for resume)

```markdown
# adopt-run
- adoption_root:
- git_root:
- mode: retrofit
- phase: survey | interview | draft | done
- interview: on | skipped
- corpus_root:
- started: YYYY-MM-DD
- maintainer:

## Evidence cards
## Rounds
## Writes
```

The journal is gitignored by default (`--persist-run` defaults off). A package-local `.llp/.gitignore` listing `adopt-run.md` is enough. Receipts never live here.

## Survey

> **Recipe (advisory)** — stop as soon as a later stop condition fires; do not finish the list.

**Read order**

1. **Identity.** `package.json`, `README.md`, native-module manifest, existing `llp/`, existing `AGENTS.md`/`CLAUDE.md` at this root and at git root.
2. **Shape.** Top-level directories; count files by extension; name entry points. Do not recurse into `node_modules/`, `build/`, `.git/`.
3. **Public API.** Exported surface and types. Treat JSDoc `@hidden`, `@platform`, and "Note"/"deprecated" blocks as evidence, not as LLP copy.
4. **User-facing docs (one hop).** README links and `homepage`. Quote; do not rewrite.
5. **CHANGELOG headings only.** Breaking changes, repeated bug themes. Read bodies of the last ~3 clusters, not the whole file.
6. **Git, path-limited to the adoption root.**
   - `git shortlog -sn -- <root>` — who to interview.
   - `git log --oneline -40 -- <root>` — recent themes.
   - `git log --oneline --grep='workaround\|hack\|revert\|don't\|breaking\|rewrite' -i -- <root>` (cap 40).
   - One `git show <sha> --stat` on at most 3 landmark commits.
7. **Invariant-shaped code.** Restriction comments; platform branches that look like policy; test names. Cap: 8 files opened in full.
8. **Subsystem candidates.** 5–10 names for the interview shortlist (LLP 0001 §2).

**Numeric stop conditions** (today's-model brakes; the scope boundary and confirm-before-survey are parent contract):

- **Budget:** 25 files fully read, or ~8k lines of source, whichever first. Directory listings and changelog headings do not count.
- **Saturation:** two consecutive card batches that do not produce a new question class.
- **Time-box:** one survey pass per invoke; leftover files become Phase 2 `llp-create` fuel.
- **File-count brake default:** ~2,000 source files under the resolved root, excluding `node_modules/` and `build/`. Halt and re-ask (LLP 0001).

**Must not**

- Walk the git root when the adoption root is a package.
- Dump `git log` into an LLP.
- Treat test coverage as a map of invariants without quoting a test name.
- Scrape `.env`, credentials, signing keys, or `secrets/` into cards. If a commit message looks like a secret, drop the card and note "redacted."
- Fetch GitHub issues/PRs unless the maintainer has authorized network and the commit already cites a number. Prefer the commit body and CHANGELOG link text already in-tree.

## Interview

### Question classes

> **Recipe (advisory)** — ask from evidence, not from a 20-question form.

| Class | What it extracts | Typical fuel |
|---|---|---|
| **Job-to-be-done** | What this package is *for*, vs. adjacent packages | README vs. actual API |
| **Invariants / never-simplify** | The simplify test ([LLP 0004](./0004-design-principles.principles.md#the-simplify-test)) | Restriction comments, serial queues, "do not" JSDoc |
| **Rejected alternatives** | Why not unify platforms / why not library X | Rewrite commits; platform splits |
| **Incidents** | Lessons that still shape code | CHANGELOG regressions |
| **Public-API freeze** | What an agent must not rename, loosen, or "clean up" | Stable identifiers, type strings, plugin-owned permissions |
| **In flux** | What *not* to document as settled | Unpublished CHANGELOG; leftover folder names |
| **Agent-failure modes** | Where locally-plausible code is globally wrong | Warnings in source; web/native divergences |
| **Stale docs** | Where README / user docs lag the code | Install instructions the build no longer needs |

Do not walk the table in order. Pick the 2–4 cards with the highest "an agent will get this wrong" score. Prefer invariants, incidents, and API freeze over job-to-be-done (the README already covers job-to-be-done; asking it first produces a restatement).

### Cadence

> **Recipe (advisory)**

- **Round size:** 2–4 questions. Never more than 4. Each question is one screen, cites the evidence, and asks for a constraint or a correction — not "tell me about the architecture."
- **Rounds:** default 2. After round 2, ask "draft now, or one more round?" Hard cap 3 rounds (~12 questions) per invoke. Further depth is `llp-create` on a named subsystem.
- **Stop when any of:** 5–10 `[confirmed]` don't-simplify constraints; maintainer says stop; two consecutive "I don't know" on the high-leverage cards (offer a delegate, then draft); round cap.
- **One question, one concern.** Do not bundle unrelated cards into a single prompt.

### Recording answers

```markdown
## Round 2 · 2026-08-25 · Alan Hughes
### Q: serial photo queue
- Evidence: CameraPhotoCapture.swift:20-25, CHANGELOG 57.0.3 #47477 #47816
- Answer: "Never parallelize full-res processing. Jetsam on iPhone SE-class."
- Claim: `[confirmed]` (Alan Hughes, 2026-08-25) Full-resolution photo processing is serial with per-item autorelease; overlapping pipelines jetsam small devices.
- Status: confirmed
```

When drafting, copy the claim with the tag. The journal is the audit trail; the LLP is the living document. If they conflict later, `llp-maintain` wins from the LLP.

### "I don't know" / "ask so-and-so"

- Record `unknown` / `delegate: <name>`.
- Keep the underlying observation `[observed]`; optional `[inferred]` hypothesis *only if the maintainer asked for one*.
- If a delegate is named and is in `git shortlog`, offer to pause, or leave a `Questions for <name>` section in LLP 0000.
- Do not silently skip the card.

### Skip-interview

`--skip-interview` is for unattended experiments and maintainers who will review a draft asynchronously. It does not lower provenance (LLP 0001). To run the interview later: `/llp-adopt --resume` with `interview: skipped`. That path does not re-survey and does not silently overwrite skip-path Drafts — it interviews, then rewrites Drafts via diff-and-ask.

## Resume

> **Recipe (advisory)** — matching rules are load-bearing for implementers.

**Precedence:** a more specific `interview:` value beats `phase` alone. Match `interview: skipped` before any `phase: done` row. After `--skip-interview` the journal is typically *both* `phase: done` and `interview: skipped`; that case is the skipped row, never the done row.

| State | `/llp-adopt --resume` (and bare `/llp-adopt` at a root that already has `llp/`) |
|---|---|
| `phase: survey` | Continue from the last completed step; do not re-list the tree. |
| `phase: interview` | One-screen recap (N cards, M confirmed, last question) and continue the round. |
| `phase: draft` | Diff generated files vs. current tree; never overwrite user edits. |
| `interview: skipped` (any phase after survey, including `done`) | Run the interview against the existing deck; then rewrite Drafts via diff-and-ask. Do not re-survey. This is the **only** match for a skip-path corpus. |
| `phase: done` **and** `interview: on` and `llp/0000` exists | Offer **extend** (new cards / new subsystem via interview) or **stop**. Never a second 0000. Does **not** match `interview: skipped`. |
| Journal missing, `llp/` present | Extend. Bare `/llp-adopt` at a root that already has `llp/` is always extend. |

## First-pass shape

The quality bar is LLP 0001 §6. Recipe for what to write:

| Doc | Type | When |
|---|---|---|
| `llp/0000-<slug>.explainer.md` | Explainer, `**Role:** Root` | Always. Half-page to ~2 pages. Map + confirmed invariants + "in flux" + links to user docs. |
| 0–2 subsystem docs | Decision or Explainer | Only if the interview produced a cluster that would bury 0000. Decision when the interview captured a choice still in force; Explainer when the job is a map. |
| Adoption plan | a section of 0000 | What was *not* written, proposed `@ref`s, hand-off. Prefer a section of 0000 over a Plan LLP. |

Do not write: a chronology; a per-platform mirror of the public types; a Principles doc of platitudes; anything whose only source is `[inferred]`.

Order when drafting: confirmed claims first, then `[observed]` structure, then a short `[inferred]` section labelled as such — or omit it. Proposed `@ref` list at the end of 0000. Apply none of them in the adopt run.

## Worked example: `expo-camera`

> **Recipe (advisory)** — falsifiable against HEAD of `packages/expo-camera`. It will go stale; that is allowed for recipes. The first live dogfood is a smaller package (`expo-keep-awake`); camera is the motivating failure mode this protocol has to survive.

**Survey fragments observed 2026-08-25:**

- `ios/Current/CameraPhotoCapture.swift` lines 20–25: serial queue, `autoreleaseFrequency: .workItem`, comment *overlapping full-res photo pipelines can jetsam small devices*.
- CHANGELOG 57.0.3 / Unpublished: orientation from the camera's own scene (#48315); deferred photo delivery disabled (#47816); UI hang / oversized files (#47477); ZXing fallback type-string regression after companion-pod extraction (#47613 / #44726); `RECORD_AUDIO` removed from the manifest so the plugin owns it (#45132); `selectedLens` moved to stable `deviceType` because `localizedName` is locale-dependent (#42916).
- `ios/Current/BarcodeScanner.swift` `NSClassFromString("ExpoCameraZXingProvider")`.
- `src/web/WebCameraUtils.ts` desktop `facingMode` / `OverconstrainedError` hack.
- `src/CameraView.tsx` warns that `<CameraView>` does not support children.
- README still tells bare Android apps to add a `cameraview` maven repo — likely stale relative to CameraX-in-tree.
- Landmark history: `fe9348d` introduce next; `c003f35` promote next to stable (#28226). Alan Hughes is the modal author.

**Round 1, question 1 — invariants / never-simplify**

> In `CameraPhotoCapture.swift` the processing queue is serial with per-item autorelease, commented as avoiding jetsam on small devices. CHANGELOG 57.0.3 also disables deferred photo delivery because it hung the capture promise on iOS 17+ (#47816) and moves full-res work off the main thread to stop UI hangs (#47477).
>
> If an agent "simplified" this to concurrent processing, re-enabled deferred delivery, or folded processing back onto the session queue, what would actually break? Are any of those comments now stale?

**Round 1, question 2 — public-API freeze + incidents**

> Three recent changes look contractual: (1) `selectedLens` uses stable `deviceType` rather than `localizedName` so programmatic selection survives non-English locales (#42916). (2) ZXing fallback barcode `type` strings (`pdf417` vs `org.iso.PDF417`) regressed when `ExpoCameraBarcodeScanning` was extracted and had to be restored (#47613 / #44726). (3) `RECORD_AUDIO` left the Android manifest so `recordAudioAndroid` is plugin-owned (#45132); README still shows it as a manual `<uses-permission>`.
>
> Which of these are frozen public contracts vs internal? What else belongs on a "never clean this up" list?

**Round 1, question 3 — rejected alternatives / in flux**

> The JS API sits on CameraX, AVFoundation (`ios/Current/`), and getUserMedia. `camera-next` was promoted to stable in #28226. Barcode scanning is optionally a companion pod discovered by class name.
>
> What must stay platform-divergent? Where would a unifying refactor be a bug? Is `ios/Current/` a leftover name or a still-meaningful split? Should an Active document mention `camera-next`, or is that history?

**Do not ask in round 1:** "What does expo-camera do?" (README). "Walk me through the file tree." (survey already did). "Should we document every CHANGELOG entry?" (entire-history pitfall).

## Failure modes

| Failure | Mitigation |
|---|---|
| Invented rationale that sounds right | Interview-before-draft; provenance tags; `[inferred]` stays `Draft` |
| Interview restates the README | Every question cites a card; job-to-be-done is last |
| Survey never stops in a monorepo | Walk-up to nearest package; confirm-before-survey; file-count brake; 25/8k budgets |
| Orient/create from git root miss the nested corpus | Walk-up discovery (LLP 0001); adopt closing message names the root |
| Resume re-surveys / overwrites prose | Resume table: `interview: skipped` beats `phase: done`; diff-and-ask; never a second 0000 |
| `--skip-interview` used to ship | No `[confirmed]` without a named human; docs stay `Draft` |
| Secrets from git history land in LLPs | Redaction; no `.env`/`secrets/`; cite commit subjects, don't paste bodies |
| Fatigue → rubber stamps | 2–4 questions/round, cap 3, "draft now" is always valid |
